# Итог Validation 2A.1

По замороженному новому контракту повторно размечены 115 слепых срезов для R01a/b/c, R02, R03 и R04. Независимая проверка охватила 30 срезов: по шесть D3, D7, T25, T50 и T80, все 23 сделки представлены. Исходы сделок не открывались и с метками не сравнивались.

**Числовой ориентир** (≥85% точного согласия и ≤10% содержательных расхождений) прошли R04 — 26/30, 86,7% — и отдельный компонент R02 `explicit_miss` — 27/30, 90%. R01a/b/c набрали 73,3–76,7%; R03 — 46,7%; весь производный R02 — 46,7%. Остальные семь компонентов R02 не прошли ориентир.

R04 — лучший кандидат, но в контрольной выборке ни один разметчик не выбрал `NO`; проверены `YES` и `UNKNOWN`, а заявленная граница `NO/UNKNOWN` остаётся непроверенной. Для `explicit_miss` большинство ответов `UNKNOWN` (26/30 и 27/30), поэтому успешная цифра не подтверждает качество всей цепочки R02. **Без дополнительной проверки ни один из переработанных признаков сейчас не рекомендован к заморозке для holdout.** Эти провалы зафиксированы без изменения контракта.

Jev должен извлекать узкие текстовые факты: роль, действие и контрольную точку одного текущего решения; сведения о клиентских обязательствах; активную техническую задачу и достаточность данных для неё; проверяемое техническое содержание клиента. Код должен составлять уровень R01 из трёх ответов одного gate, вести журнал обязательств и сроки R02, а для R04 хранить накопленный факт `YES`. Истечение срока без явного подтверждения срыва остаётся `UNKNOWN`.

Временная проверка: R04 не терял `YES`; у R01c был один переход `YES→NO` при том же ключе gate; R03 не терял достаточность при неизменной задаче. Ограничения — 30 контрольных срезов, редкость классов `NO` для R04 и подтверждённых повторных срывов для R02. Прогностическая способность не измерялась; holdout и интеграция не выполнялись.
